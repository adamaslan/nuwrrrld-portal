01The self-improving loop

The dossier's closing recommendation was to make the memory-to-command path explicit. These two commands do exactly that: pain gets logged, mined, and absorbed — and the next bottleneck is one you haven't seen yet.

Signal
/friction
Log one bottleneck line to log.md the moment you hit it.
→
Mine + propose
/suggest-commands
Tally log + incidents + PR comments vs. threshold; propose automation.
→
Curate
you adopt
Vouch for it; write the command; add it to the suite.
→
Absorb
suite grows
The friction never recurs; the loop gets cheaper over time.
Threshold to propose: a bottleneck must recur ≥ 3 times — or ≥ 1 time if it caused or risks a production incident. Incident-cost friction jumps the queue. /suggest-commands proposes only; adoption is a human yes.

04A new global rule

One convention added at the ~/.claude/ tier — it applies to every project, not just this repo.

artifact-and-local-html.md — whenever an HTML page is requested, produce both a local .html file on disk and a published artifact, from one authoring pass. Each covers the other's gap: the file is durable and diffable, the artifact is shareable and previewable. This very page is the rule's first application.

05Why it holds together

  • Self-documenting. Every command orients from the wiki and ingests back into it; the suite has an entity page, and the loop has a concept page.
  • Self-improving. /friction → /suggest-commands turns recurring pain into proposed automation, on a threshold you control.
  • Limit-resilient. /resume-safe checkpoints into the wiki — the durable memory — so a long automated run survives the token wall instead of losing its place.
  • No dangling links. The three pages the bugmerge1 incident and the dossier referenced now exist and cross-link into the graph.
