# Decision: Precompute Batch AI at the Free-Tier Quota Reset

## Decision

Batch AI artifacts — work that does not need a user present — are generated by a **scheduled job running just after OpenRouter's UTC-midnight free-tier reset**, stored in the `precomputed_ai` Neon table, and served by routes as ordinary cached reads at **zero model quota cost**.

The first artifact kind is `portfolio_health_ai`. `/api/portfolio/health-ai` checks for a precomputed row before spending any quota, and falls through to its existing live path on a miss.

## Date

2026-08-18

## Context

OpenRouter's free tier caps the **whole API key** at 50 requests/day, resetting at UTC midnight ([[entity-openrouter-client]] known-failure #3). Batch AI work and interactive Nu AI chat draw on that single bucket, and batch reliably wins — it runs on page load, before any user asks a question. The observable result is a user asking something in the afternoon and finding the day's allowance already spent on a narrative nobody was waiting for.

The reframing that produced this decision: **free-tier quota is a renewable resource with a schedule.** It is not a fixed budget to ration but a recurring allowance with a known reset time — and a scheduler is the right tool for spending a scheduled resource. Nothing about the batch work requires it to happen during a request; it was only there because that is where the code already lived.

## Alternatives considered

- **Ration at request time** (per-user quotas, feature gating). Preserves quota by denying features, which is the outcome this avoids. It also cannot distinguish work that *had* to be live from work that merely happened to be.
- **Pay for capacity.** Solves it immediately and contradicts [[decision-free-tier-model-chain]]'s $0 intent. Still the right answer if usage outgrows precompute, but it buys nothing that scheduling doesn't, at this scale.
- **Cache live responses opportunistically.** The first user of the day still pays full latency *and* full quota, and cold portfolios never warm. Precompute inverts this: the expensive path runs when nobody is waiting.
- **Precompute per user.** Rejected — the payload is keyed on the *ticker set*, not the user, so per-user generation would multiply quota spend for byte-identical output. `subjectFromTickers()` collapses identical watchlists to one shared artifact.

## Consequences

- **Interactive calls get the whole daily allowance.** The batch narrative no longer competes with Nu AI chat.
- **Two bounds on spend, deliberately redundant.** `MAX_SUBJECTS` in the job and `MAX_SUBJECTS_CEILING` in the route. A precompute job that exhausts the allowance is strictly *worse* than none, since it starves the path it exists to protect. The route also stops early on a 429 rather than burning retries against an allowance already gone.
- **Staleness becomes visible, not hidden.** Reads return `ageMinutes` and `generatedAt`, and the response is flagged `precomputed: true`, so the UI can label "as of {time}" rather than presenting hours-old commentary as current — the honest-lesser rule of [[concept-graceful-degradation]].
- **Only the JSON path is served precomputed.** SSE callers expect a token stream; synthesizing one from stored text adds latency for no benefit, so they fall through to the live path.
- **Degrades to current behavior.** Every DB function is try/catch → null/no-op, so an unreachable Neon or an un-migrated table means "no precomputed value" and the live path runs exactly as before. Safe to deploy before `npm run db:migrate`.
- **One scheduler, not two.** GHA (`.github/workflows/precompute-ai.yml`) and Modal (`deploy/precompute-ai/modal_app.py`) are a deliberate multi-platform pair matching the `deploy/free-model-refresh/` precedent — but running **both** doubles quota spend for identical output. GHA is the simpler default; Modal wins if this outgrows the GHA job ceiling or needs per-ticker fan-out.

## Validated by

- `__tests__/precomputed-ai.test.ts` — pins `subjectFromTickers` order-independence, case/whitespace normalization, de-duplication, and `split()` round-trip. This is the cache key, so instability in it silently re-spends the quota the feature exists to conserve — and a miss looks like a cold cache, not a bug.
- `next build` — `/api/pipeline/precompute-ai` registers; full unit suite green (262 passing).
- ❓ **Not yet validated end-to-end against a real schedule.** The endpoint and both schedulers exist; no nightly run has executed. The `quotaExhausted` warning path in particular is untested against a live 429.
