Root causes (confirmed from production telemetry, not guessed).
  1. Malformed STRIPE_SECRET_KEY in Vercel production. Vercel runtime error on /api/stripe/checkout: StripeConnectionError → TypeError: Invalid character in header content ["Authorization"] (ERR_INVALID_CHAR). Classic signature of a stray trailing newline/whitespace pasted into the Vercel env var value. Because the Stripe call wasn't wrapped in try/catch, this became an unhandled 500 with no JSON body — the checkout button's fetch(...).json() failed silently and showed a generic "Could not start checkout" alert.
  2. Clerk is serving a Development instance on the production domain. curl https://financial.nuwrrrld.com/sign-in returns a pk_test_... publishable key (a *.clerk.accounts.dev dev instance), not a pk_live_... production instance. Dev instances have MAU/sign-up caps and cookie/domain restrictions not meant for a live custom domain.

Part A — Code fixes already shipped

Done in this repo. Verified with npx vitest run --project unit (170 passed) and npx tsc --noEmit (clean).

1
Defensive error handling on Stripe call sites. app/api/stripe/checkout/route.ts and app/api/stripe/portal/route.ts now wrap every Stripe SDK call in try/catch and return 502 with a real { error: "..." } body instead of an unhandled 500 with no body. CheckoutButton.tsx / ManageBillingButton.tsx now show that message in the alert instead of a generic "try again."
2
Extended /api/health to catch both failure classes before a user hits them: checkStripe() now flags unset/placeholder STRIPE_PRICE_MONTHLY/STRIPE_PRICE_ANNUAL as not_configured, and a new checkClerk() flags a pk_test_... key running with VERCEL_ENV=production as degraded.
3
Hardened publicMetadata reads. Added parseSubscriptionMetadata() to lib/subscription.ts — validates subscription_status against the known enum (falls back to free) and validates numeric timestamps. Replaced ad-hoc as casts in app/api/stripe/subscription/route.ts, app/api/nuai/route.ts, and app/dashboard/page.tsx.
4
Regression tests added. __tests__/subscription.test.ts (pure-function coverage for tierFromStatus, hasEntitlement, isTrialExpired, parseSubscriptionMetadata) and __tests__/stripe-checkout.test.ts (pins the incident: a mocked Stripe SDK throw must come back as 502 JSON, never an unhandled crash).

Part B — Manual steps still required

These need account access I don't have (the real Stripe key value, and your Clerk Dashboard). Do these to actually restore checkout in production.

B1. Rotate STRIPE_SECRET_KEY in Vercel

  1. Open the Stripe Dashboard → Developers → API keys and copy the Secret key (starts with sk_live_ for production).
  2. Run vercel env rm STRIPE_SECRET_KEY production to remove the current (malformed) value.
  3. Run vercel env add STRIPE_SECRET_KEY production and paste the key without a trailing newline — if pasting from a terminal, use 
    printf '%s' "sk_live_xxxxxxxx" | vercel env add STRIPE_SECRET_KEY production
    which avoids the trailing \n that echo/copy-paste commonly adds.
  4. Repeat for STRIPE_WEBHOOK_SECRET, STRIPE_PRICE_MONTHLY, and STRIPE_PRICE_ANNUAL if there's any doubt they were pasted the same way.
  5. Redeploy: vercel --prod (or push to main if auto-deploy is configured).
  6. Verify: curl https://financial.nuwrrrld.com/api/health | jq '.stripe' should show "status": "ok".

B2. Promote a Clerk Production instance

  1. Open the Clerk Dashboard for the NuWrrrld application.
  2. Go to Deploy → Production (or the environment switcher) and follow the prompt to create/promote a Production instance.
  3. Add and verify the production domain financial.nuwrrrld.com (Clerk will ask you to add DNS TXT/CNAME records for domain verification).
  4. Once verified, copy the new pk_live_... and sk_live_... keys from Production → API Keys.
  5. Update Vercel: 
    vercel env rm NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY production
vercel env add NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY production
vercel env rm CLERK_SECRET_KEY production
vercel env add CLERK_SECRET_KEY production
  6. Redeploy: vercel --prod.
  7. Verify: curl https://financial.nuwrrrld.com/api/health | jq '.clerk' should show "status": "ok" with no pk_test_ warning.
