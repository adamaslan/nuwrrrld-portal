Running nulogdash

A feature-level end-to-end sweep of the portal: it calls every real API route in docs/nulogdash-inventory.json against your local dev server, then writes a pass / fail / blocked / not_run verdict for each one to .nulogdash/latest.json.

Preconditions· Run the sweep· View results· Standalone HTML report· Reading blocked/fail· Command reference

01 Preconditions

All four need to be true before a sweep will tell you anything real. Skip one and the sweep still runs — it just reports most features as blocked instead of exercising them.

  • next dev is running (npm run dev) — the sweep hits http://localhost:3000 by default, overridable with NULOGDASH_BASE_URL.
  • .env.local has the same keys /local-check verifies (Neon, OpenRouter, Stripe, GCP backend). Run that first if you're not sure.
  • NULOGDASH_SESSION_COOKIE is set to a real Clerk __session cookie value for a dedicated test user — copy it from browser devtools after signing in as that user. Without it, every auth-required feature reports blocked, not silently skipped.
  • NULOGDASH_ADMIN_EMAILS (comma-separated) includes your own email, or /dashboard/nulogdash won't let you view the results.

Want the sweep's test user to actually have data (a watchlist, a scored portfolio) instead of hitting empty-state 503s that report a true but meaningless pass? Run the fixture seed first:

# idempotent — only adds watchlist rows for the dedicated E2E test user
node --env-file=.env.local scripts/nulogdash-fixture.mjs

# check whether seeding already happened, without writing anything
node --env-file=.env.local scripts/nulogdash-fixture.mjs --check

02 Run the sweep

1

Regenerate the feature inventory

Rebuilds docs/nulogdash-inventory.json from app/api/** and warns on drift — a route added or removed without the inventory catching up.

npm run nulogdash:inventory
2

Run the full sweep

Chains step 1, then calls every feature's entrypoint with the session cookie above.

npm run nulogdash
# same as: npm run nulogdash:inventory && node --env-file=.env.local scripts/nulogdash.mjs
3

Or run just one feature

Fast iteration while debugging a single check — slug comes from docs/nulogdash-inventory.json.

node --env-file=.env.local scripts/nulogdash.mjs --feature <slug>

03 View the results

With next dev still running, open http://localhost:3000/dashboard/nulogdash — it renders .nulogdash/latest.json as a live matrix. This is the primary way to read a sweep; nothing else in this guide replaces it.

04 Generate a standalone HTML report

For sharing a sweep outside the running dev server — in a PR, a Slack thread, an incident writeup — scripts/nulogdash-report.mjs renders one sweep as a single self-contained HTML file. It only reads .nulogdash/; it never calls the dev server, the database, or a model.

npm run nulogdash:report
# same as: node scripts/nulogdash-report.mjs

# a specific past run instead of the latest sweep
node scripts/nulogdash-report.mjs --run <runId>

# open the generated file immediately
node scripts/nulogdash-report.mjs --open

# change where the HTML is written (default shown)
node scripts/nulogdash-report.mjs --out-dir docs/nulogdash-runs

The report groups every blocked / not_run feature by its redacted reason, so thirty-eight identical "no session cookie" rows read as one root cause instead of thirty-eight separate lines.

05 Reading a blocked or failed sweep

Blocked isn't broken. A feature reporting blocked almost always means a precondition from step 01 is missing, most often NULOGDASH_SESSION_COOKIE. Fix the precondition and re-run — don't start debugging the route itself until the sweep can actually reach it.
Status meanings
StatusMeaningWhat to check first
passRoute was called and returned the expected shape.—
failRoute was called and returned something wrong.The redacted reason field in the report — don't re-run the request to see raw output.
blockedA precondition stopped the sweep from calling the route at all.NULOGDASH_SESSION_COOKIE, then the other three preconditions in order.
not_runFeature was intentionally excluded from this sweep.The excluded: prefix on its reason.
