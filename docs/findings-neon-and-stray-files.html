1. Portal build failure (Neon DB) Resolved — transient

The npm run build pre-flight failed with a 5-minute HeadersTimeoutError connecting to the Neon database. Root cause traced and confirmed not a code or config problem.

What's actually going on

package.json wires a prebuild step: node scripts/db-migrate.mjs runs before every next build (including on Vercel), applying lib/db/schema.sql to Neon. It's idempotent (IF NOT EXISTS everywhere) and reads DATABASE_URL from .env.local when not already in process.env.

http_code=400 in 0.41s — expected response shape for a bare GET on a Postgres-over-HTTP endpoint; confirms the host is reachable and fast

Completed clean — ƒ Proxy (Middleware) present as expected
Verdict: one-off network blip (likely the background shell's first connection hit a stale/cold path in the Neon pooler, or a momentary local network hiccup) — not a credentials, DNS, firewall, or code issue. Portal build is green as of this investigation.

Suggested follow-up (optional, not applied)

scripts/db-migrate.mjs has no request timeout of its own, so a bad connection silently rides the underlying driver's default (which is what produced the 5-minute wait). A short explicit timeout + one retry would turn a 5-minute hang into a fast, clear failure next time this happens.

2. Mobile "stray" files — Not stray. Genuine, pre-existing broken code.

npx tsc --noEmit in gcp3-mobile reported ~35 errors across api/, app/(tabs)/, app/_layout.tsx, app/sign-in*.tsx, and three components/* files. These are tracked, committed, in-history files — not orphaned scratch work — but they've apparently never actually been typechecked before now.

Root cause #1 — missing path-alias config (breaks 13 files)

13 files import via @/lib/.... Nothing in this repo defines that alias:

  • tsconfig.json extends expo/tsconfig.base only — no "paths" override
  • expo/tsconfig.base.json itself defines no @/* mapping
  • No babel.config.js, no metro.config.js, no jsconfig.json, no package.json "imports" field anywhere in the repo

The target files the alias points at do exist on disk (lib/config-validator.ts, lib/ui/theme.ts, lib/auth-provider.tsx, etc.) — only the alias resolution is missing. This would break at Metro bundle time too, not just under tsc.

Root cause #2 — three deps used but never installed

PackageUsed byIn package.json?
nextapi/config.ts, api/health.ts, api/metrics.ts, api/webhooks/clerk.tsNever (checked full git history)
svixapi/webhooks/clerk.tsNever
expo-notificationslib/pushNotifications.tsNever

The api/ folder was added in commit 5a4bb2a — "feat: implement phase 4 & 5 — resilience patterns and monitoring" — authored by Claude Haiku 4.5 (per commit trailer). It adds a health-check endpoint, metrics collection, config validation, and a Clerk webhook handler written in a Next.js/Vercel-serverless-function shape (NextApiRequest/NextApiResponse), inside an Expo Router app that has no Next.js dependency at all. It reads as generated code that assumed the wrong runtime and was never executed to verify.

Root cause #3 — a genuinely missing file

backend/schemas/signal.ts is imported by three components (EvidenceExpandedView.tsx, SignalMatrixRow.tsx, SignalCard.tsx) — the backend/ directory doesn't exist in this repo at all.

Root cause #4 — a handful of real (small) type errors

Independent of the above: app/market.tsx:34 (unknown not assignable to state setter), app/sign-in.tsx:109 (string | null vs string), possibly-undefined signIn/signUp in the 2FA and sign-up flows, and a boolean | undefined vs boolean | null mismatch in lib/auth-provider.tsx:136.

Why this went unnoticed

  • No .github/workflows directory exists in gcp3-mobile — no CI at all
  • package.json "scripts" has no tsc/typecheck entry — npx tsc --noEmit has apparently never been run as part of this project's normal workflow
Verdict: this is real, standing technical debt in gcp3-mobile, unrelated to any work in the current session. It predates and is independent of the in-progress uncommitted changes on feat/mobile-interactivity-batch (lib/usePortfolio.ts, screens/PortfolioScreen.tsx — neither of which appears in the tsc error list).
