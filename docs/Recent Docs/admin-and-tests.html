01 Admin features

There is no admin surface in this app today. No admin routes, no admin API, no role-based gate.

No admin panel exists

There is no app/admin/** directory, no /api/admin/* route, and no admin UI components anywhere in the codebase. The one trace of the word "admin" is NULOGDASH_ADMIN_EMAILS, declared in the env schema (lib/env.ts) but never read by any middleware, route, or component — a reserved config key, not a working feature.

What middleware.ts actually enforces is user-level auth only, via Clerk — no privileged role or org-permission check anywhere:

03 Coverage gaps

The suite is dense on pure-function business logic and thin everywhere else.

  • Route handlers: only stripe-checkout.test.ts exercises an actual API route. Every other endpoint — /api/webhooks/*, /api/portfolio/*, /api/holdfold/*, /api/backtest/* — has no request/response-level test.
  • Auth & middleware: no test asserts that middleware.ts actually blocks unauthenticated requests to protected routes, or that the PORTAL_PUSH_SECRET bearer path behaves correctly under a wrong or missing secret.
  • UI & components: zero React component tests and zero end-to-end/browser tests — no Playwright, Cypress, or Testing Library setup exists.
  • Admin controls: not applicable — there is nothing to test, since no admin feature is implemented yet.
