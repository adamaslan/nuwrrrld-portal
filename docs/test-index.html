Preflight project: preflight 6 tests · runs first, gates everything else

Credential shape and liveness — never logs a secret value, only asserts prefix, whitespace, and whether the provider actually accepts the key. A revoked OPENROUTER_API_KEY fails once here instead of producing forty confusing red tests downstream.

e2e/preflight/credentials.spec.ts

  • shape

    AI + auth + billing keys are present and well-formed

    Checks OPENROUTER_API_KEY, ANTHROPIC_API_KEY, CLERK_SECRET_KEY, NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY, STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET, and DATABASE_URL exist and start with the expected prefix (sk-or-v1-, sk-ant-, etc.), with no leading/trailing whitespace.

  • EXPOSE

    placeholder values that pass a presence check but fail at runtime

    Flags whsec_placeholder_*-style values in Stripe/portal-push/IP-hash secrets — the class of value that satisfies "is it set?" and then silently rejects every real request.

  • EXPOSE

    production running on development-tier keys

    Production-only guard: fails if NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY or STRIPE_SECRET_KEY are still pk_test_/sk_test_ while VERCEL_ENV=production.

  • liveness

    OPENROUTER_API_KEY is accepted by the provider

    One real, free call to /v1/models — a well-formed but revoked key passes every shape check and only fails here.

  • liveness

    STRIPE_SECRET_KEY is accepted by Stripe

    One real, free call to /v1/balance to confirm the key is live, not just shaped correctly.

  • liveness

    MCP_BACKEND_URL points at a live GCP Cloud Run service

    Hits the backend's own /health; a 5xx here is the Cloud Run cold-start signature, not necessarily a real outage.

Health project: health 3 tests · depends on preflight

Wraps the app's own aggregate dependency probe (GET /api/health), which already fans out to MCP, Neon, Stripe, OpenRouter, and Clerk in parallel.

e2e/health/dependencies.spec.ts

  • check

    every dependency is reachable and configured

    Asserts /api/health returns 200 and every one of mcp/neon/stripe/openrouter/clerk reports ok. Prints the full verdict on failure — statuses and latencies only, never key material.

  • EXPOSE

    latency budget — a dependency slow enough to time out user requests

    Flags any dependency over a 2000ms budget, so a slow-but-technically-"ok" backend is caught before a user hits it as a timeout.

  • EXPOSE

    frontend renders a usable page when /api/health reports down

    Mocks a 503 health response and checks for a visible alert banner on /dashboard. Currently expected to fail — DashboardCockpit has no such banner yet; this documents the gap.

CI / automation integrations project: ci 5 tests · no browser, no auth

Covers the weekly refresh-free-models.mjs job and its GitHub Actions workflow — spawns the real script as a subprocess and checks the workflow YAML's structure. No page, no mocking: these prove the CLI's own safety invariants.

e2e/ci/refresh-free-models.spec.ts

  • safety

    --dry-run never writes lib/openrouter.ts, even when the run otherwise succeeds

    Spawns the real script with --dry-run --no-probe and diffs the target file before/after. Needs live network to OpenRouter's public model list — a "fetch failed" here means check connectivity, not the flag.

  • safety

    refuses to run --probe (the default) without OPENROUTER_API_KEY

    Confirms a missing key hard-fails loudly (exit 1, clear stderr) instead of silently no-op’ing — the failure mode that would let a misconfigured GHA secret through unnoticed.

  • EXPOSE

    MIN_WORKING safety floor leaves the target file untouched on a near-total probe failure

    Feeds a deliberately invalid key through the real probe path (every model call 401s) and confirms the script refuses to write a chain that would strand the app on zero working models.

  • shape

    workflow env forwards the same OPENROUTER_API_KEY name the script reads

    Cross-checks the literal env var name in refresh-free-models.yml against what the script actually reads — catches a renamed secret on one side going silently stale.

  • shape

    workflow requests contents:write + pull-requests:write, matching what create-pull-request needs

    Confirms the workflow's permissions block has what peter-evans/create-pull-request needs — missing either fails after the costly probe pass already ran.

Auth setup project: auth-setup 1 test · gates the frontend tier

Signs in a dedicated Clerk test user once via @clerk/testing and saves the session to playwright/.auth/user.json, reused for up to 6 days before re-authenticating automatically.

e2e/auth.setup.ts

  • setup

    authenticate

    Skips itself if the cached session is under 6 days old. Otherwise signs in with E2E_CLERK_TEST_EMAIL/E2E_CLERK_TEST_PASSWORD and confirms the redirect to /dashboard actually happened before saving state.

Frontend fault injection project: frontend 16 tests · already signed in

Route-level fault injection against real components — mocked 429s, stalled SSE, contract-drift payloads, and DOM-vs-payload fidelity checks. Three files, one per surface.

e2e/frontend/nuai-fault-injection.spec.ts — Nu AI chat (/dashboard/nuai)

  • EXPOSE

    OpenRouter HTTP 429 leaves the error unrendered or the button stuck disabled

    Mocks a 429 and checks the error string actually reaches .nuai-error and the send button re-enables, rather than getting silently swallowed.

  • EXPOSE

    a stalled SSE stream leaves the typing indicator running forever

    Fulfils a single SSE chunk and never closes the stream — checks whether .nuai-typing ever clears without a client-side timeout.

  • EXPOSE

    a 403 upgrade_required response surfaces the specific upgrade copy, not a raw HTTP 403

    Confirms the Pro-upgrade message renders, not a generic status-code string.

e2e/frontend/portfolio-health.spec.ts — Portfolio Health / Track Record (/dashboard/portfolio)

  • DIAGNOSE

    gcp3 returning non-ok collapses to one generic 502

    Proves the portal's own response can't distinguish "route never registered" from "backend crashed" — both become the same flat upstream error. Root-cause diagnosis needs gcp3's own logs.

  • DIAGNOSE

    contract drift — gcp3 emits ai_grade/ai_insights, portal expects score/factors/summary

    Mocks the documented field-name mismatch and confirms it does not silently render as "Grade F for every user" — the incident's worse-than-an-error failure mode.

  • EXPOSE

    empty watchlist (204) must never render as an error

    A 204 must land on the "add tickers" empty state, not the error state.

  • DIAGNOSE

    AI narrative renders ungrounded prose without the warning banner

    Checks that an X-Portfolio-Health-Grounded: false response actually surfaces a warning — not just confident-sounding prose with no real data behind it.

  • DIAGNOSE

    HTTP-200-but-empty completion from every fallback model

    Reproduces the terminal "every free model came back empty" state and checks it surfaces the expected copy, distinct from a broken fallback chain.

  • EXPOSE

    PortfolioClient sends no Accept header on the AI health request

    Captures the actual request header sent — verified during this build-out that the header is present today; a failure here is a real regression, not confirmation of the old bug.

  • DIAGNOSE

    suggestions silently fail with a generic message, masking the actual HTTP status

    Notes that 401, 503, and a malformed body all render identically — the fix is capturing the real status, not just "error".

  • DIAGNOSE

    SIGNALS_ENGINE_URL unset vs. engine unreachable vs. malformed response — all collapse to 204

    Documents that four distinct causes in fetchBacktest() all produce the identical 204 — only server-side env inspection can tell them apart.

  • EXPOSE

    the exact 'unavailable' string does not distinguish unset config from a broken engine

    Reproduces the reported "Historical hit-rate data unavailable for JETS" state deterministically via a mocked 204.

  • DIAGNOSE

    backtest engine returns a shape that fails isBacktestResult() silently

    Mocks a plausible-but-wrong response shape (flat hit_rate instead of bucketed data) — same contract-drift failure class as the portfolio-health incident, different service pair.

e2e/frontend/signal-timing.spec.ts — Signal timing / SOXX (/dashboard/signals)

  • DIAGNOSE

    a fresh generatedAt suppresses the stale badge even for scoped-stale data

    The batch-timestamp blind spot: every ticker in one digest shares one generatedAt. A single ticker's own score can be old while the batch envelope still looks fresh, and nothing here can currently tell.

  • EXPOSE

    the confluence score and bull/bear counts rendered in the DOM must match the payload exactly

    Cross-checks the live /api/signals/digest response against what actually painted on screen — catches transcription drift between backend and pixels.

  • DIAGNOSE

    signal-policy's cacheTtlMinutes classifies an 82%-confluence bullish signal as 'hot'

    Checks a high-confluence signal's actual age against the 5-minute hot-refresh TTL it should qualify for — if it's older, the hot-refresh path isn't firing, which is the real "why does this number look stale" question.
