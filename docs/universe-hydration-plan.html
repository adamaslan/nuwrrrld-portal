Two lanes, deliberately

Modal owns the recurring nightly walk. A local script owns anything you want to watch, debug, or re-run by hand. They write through the same endpoint, so they cannot disagree about schema, validation, or idempotency.

Lane A · Modal

Nightly full-universe walk

05:00 UTC · cron

deploy/universe-hydration/modal_app.py, already written. Chunks the universe 200 symbols at a time, pulls 120 days of daily bars from Alpaca, computes RSI / MACD-cross / ADX / volatility-percentile in pandas, and POSTs token cards back to the portal. It holds a push secret and a market-data key — never a database URL, never a model key.

modal cron 05:00 UTC ├─ GET /api/pipeline/hydrate-universe?universe=stock → symbol list ├─ GET data.alpaca.markets/v2/stocks/bars ×N chunks → 120d daily bars ├─ pandas: RSI · MACD cross · ADX · vol-percentile → 0 model calls └─ POST /api/pipeline/hydrate-universe ×N chunks → ticker_cards

It fails the run below 95% coverage rather than reporting green on a partial night — the silent-degradation guard this pipeline exists to prevent.

Lane B · Local

Manual hydration you can watch

on demand · your terminal

The same walk, run from your machine against a local dev server, scoped to whatever symbol list you hand it. This is the lane that makes the Modal lane trustworthy: you see every chunk land, every card score, every rejection reason, before a cron ever runs unattended.

node scripts/hydrate-local.mjs --symbols=AAPL,NVDA,MSFT ├─ reads .env.local (ALPACA_* + PORTAL_PUSH_SECRET) ├─ same Alpaca fetch, same indicator math (JS port) ├─ POST http://localhost:3000/api/pipeline/hydrate-universe └─ prints per-symbol: score · action · dataQuality · missingFields

Also the only lane that works before Modal is deployed at all — which is today's actual state.

The base portfolio

The test user currently has 5 watchlist rows. A base portfolio makes the dashboards render something real, and gives the AI lane a portfolio to be healthy or unhealthy about.

user_devlocal000000000000000 holds AAPL, NVDA, MSFT, TSLA, SPY. That set is a reasonable spine, but it's a watchlist, not a portfolio — no positions, no cost basis, so portfolio-health has nothing to score. The plan seeds a deliberate base portfolio across sectors so the health factors (concentration, sector balance, volatility) produce a non-degenerate grade rather than a flat A or a silent F.

Firestore

Worth being precise about, because it isn't in this repo.

Firestore is reached through the gcp3 backend (~/code/gcp3/backend/) — etf_history/{SYMBOL} holds permanent ETF price history, industry_cache holds the 54-ETF signal rows, nwf_digest/latest holds the digest the portal reads. The portal has no Firestore client and no GCP credentials; it talks to MCP_BACKEND_URL over HTTP.

So "hydrate Firestore as well" means a cross-repo step: seeding etf_history through gcp3's own etf_store.py, which appends only new trading days after an initial full-history seed. That's a separate repo, a separate PR loop, and separate credentials.

Scoping note. The Firestore lane is real work but it is not on the critical path for universe coverage. The Alpaca → Neon → ticker_cards path is complete and self-contained; Firestore only feeds the 54 ETF rows, which already work. Recommend shipping the stock lane first and treating the Firestore seed as a follow-on in gcp3.

The order to run it

Each step leaves the system working and is independently verifiable. Nothing here is a rewrite — it's turning on code that already exists.

  1. Seed the universe locally, against a dev branch first

    seed-universe.mjs scrapes 518 tickers from Wikipedia. Point it at localhost:3000 before anything touches production — the script has a MIN_ROWS guard that fails loud on a parser regression, and you want to see that guard pass once. 

    PORTAL_URL=http://localhost:3000 \
  node scripts/seed-universe.mjs --dry-run
PORTAL_URL=http://localhost:3000 \
  node scripts/seed-universe.mjs

  2. Write the local hydration script

    scripts/hydrate-local.mjs — a JS port of the Modal indicator math, hitting the same POST endpoint. This is new code, and it's the only new code in the plan. It exists so hydration is observable before it's automated.

    • Same 4 indicators, same taxonomy buckets, same missingFields semantics
    • --symbols= to scope, --limit= to cap, --dry-run to print without posting
    • Per-symbol output: score, action, dataQuality, why a field is missing

  3. Hydrate a hand-picked set and read the output

    Start with the 12 base-portfolio tickers. Confirm cards land, scores are plausible, and dataQuality clears the 0.8 explain floor for stocks — which it should, since the Modal lane fills all four taxonomy inputs that gcp3's ETF payload cannot. 

    node scripts/hydrate-local.mjs \
  --symbols=AAPL,MSFT,NVDA,SPY,QQQ,VDE,XLU,TSLA,QBTS,MU,SNDK,GOOG

  4. Seed the base portfolio for the test user

    scripts/seed-base-portfolio.mjs, following hydrate-dev.mjs's production-refusal guard pattern verbatim — it refuses on NODE_ENV=production, on Vercel/CI, and on any host with a prod marker.

  5. Scale the local run to the full universe

    518 tickers, ~3 chunks, no daily cap to exhaust. This is the rehearsal for the cron — if it completes locally, the Modal lane is doing the same work on a timer.

  6. Provision the Modal secret and deploy

    One command, all four keys together. Modal secrets are replaced wholesale, not merged — setting them one at a time silently wipes the others. 

    modal secret create nuwrrrld-hydration \
  PORTAL_PUSH_SECRET=... PORTAL_URL=... \
  ALPACA_API_KEY=... ALPACA_API_SECRET=...
modal deploy deploy/universe-hydration/modal_app.py
modal run deploy/universe-hydration/modal_app.py --symbols AAPL,MSFT

  7. Disable one of the two precompute schedulers

    .github/workflows/precompute-ai.yml and deploy/precompute-ai/modal_app.py both fire 10 0 * * * at the same endpoint. Harmless while cards don't exist; a real double-spend of OpenRouter quota the moment they do.

The pattern worth noticing: the top four all fail today for the same reason, and it isn't a bug in any of them. They are all downstream of an empty ticker_cards table. One hydration run repairs four features at once.

What this plan does not fix

Stated plainly so it isn't discovered later as a surprise.

Blocker 1 stays open. Every ETF card lands at dataQuality: 0.20 because gcp3's ETF payload fills 1 of 5 taxonomy inputs. Hydrating stocks does not change this — it routes around it. The 54 ETFs remain covered-but-never-explainable until someone picks between extending gcp3's ETF scoring or accepting ETF-as-coverage-only permanently.

Alpaca's free tier is IEX-only, not full SIP. Fine for the S&P 500 and Nasdaq-100 — the daily bars reconcile. For illiquid long-tail names, some sessions will have thin or absent prints, producing gaps. This is an argument for tiering the universe, not against Alpaca.

Firestore is cross-repo. The etf_history seed lives in gcp3 and is deliberately out of scope for the first hydration run.

Nothing here is intraday. This is a daily EOD lane. The Finnhub hot-set refresh is designed but deliberately deferred until staleness is a real complaint rather than an anticipated one.
