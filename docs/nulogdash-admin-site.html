What it is

/dashboard/nulogdash is the portal's only admin surface today. It renders the results of the most recent nulogdash sweep — a pass over the app's features (signals, hold/fold, portfolio, Nu AI, etc.) checking whether each one actually ran end-to-end, and if not, why.

Runs are produced locally via /nulogdash in Claude Code or npm run nulogdash from a terminal, and written to .nulogdash/latest.json. The page is force-dynamic so it always reflects the latest run on disk — there's no caching to fight.

Access control

The page is gated by email allowlist, not role or plan. On load it checks the signed-in Clerk user's primary email against NULOGDASH_ADMIN_EMAILS (comma-separated env var). Non-admins get a 404 via notFound() — the route doesn't reveal itself to anyone off the list. Signed-out users are redirected to sign-in first.

The allowlist check is centralized in lib/nulogdash.ts as isNulogdashAdmin(email), shared by the page itself and by the dashboard navbar (below).

Link on the dashboard navbar

The main dashboard topbar (app/dashboard/page.tsx) now shows a nulogdash link alongside Signals, Hold/Fold, Nu AI, Portfolio, Share, Billing, and Founders — but only for signed-in users who pass isNulogdashAdmin(). Everyone else sees the same navbar with that link simply absent, matching the page's own 404-if-not-allowlisted behavior.
