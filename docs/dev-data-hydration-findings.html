Bugs found & fixed

All three were caught by running the seeder against the real dev DB — none would surface from a dry-run or syntax check. This is why the run step matters.

Bug 1 — NOT NULL violation on signal_digest_cache.generated_at

Symptom: null value in column "generated_at" ... violates not-null constraint.

Cause: the live table predates schema.sql's DEFAULT now(), and CREATE TABLE IF NOT EXISTS never back-fills a default onto an existing column — so the column is NOT NULL with no default. The production code (lib/digest-cache-db.ts) already works around this by always passing generated_at explicitly.

Fix: pass generated_at explicitly on the signal_digest_cache and holdfold_cache inserts (same latent risk).

Bug 2 — invalid UUID for the fixed dev council session

Symptom: invalid input syntax for type uuid: "00000000-0000-4000-8000-00000000dev1".

Cause: the sentinel ended in dev1 — v is not a hex digit, so it isn't a valid UUID.

Fix: switched to an all-hex sentinel dddddddd-dddd-4ddd-8ddd-dddddddddddd (valid v4 shape, obviously synthetic).

Bug 3 — pending_signals not idempotent (5/3 drift)

Symptom: after two partial runs + one full run, pending_signals held 5 rows where 3 were expected.

Cause: only the pending insert was dedup'd (by the one-pending-per-ticker unique index); the done/error inserts appended on every run.

Fix: delete this dev user's pending_signals rows before seeding the state fixtures, so re-runs converge to exactly 3. Verified: reset→3/3, plain re-run→still 3/3.
