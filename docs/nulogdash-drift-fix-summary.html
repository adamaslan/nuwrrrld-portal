§ 1Why six routes "404'd" — it wasn't a bug

/api/analyze, /api/disclaimer, /api/legal-consent, /api/privacy/{delete,export,profile} all returned an HTML 404 page to the sweep even though the route files exist and export valid handlers. Cause:

Clerk's clerkMiddleware obscures protected API routes

All six sit inside proxy.ts's isProtectedApiRoute matcher. When an unauthenticated request hits a protected API route, Clerk returns a 404 rather than a 401 — by design, so the endpoint's existence isn't leaked. The sweep runs with no NULOGDASH_SESSION_COOKIE, so every one of them 404'd. This is the same "needs a session" state as the 28 rows already marked blocked — it was just being scored as fail because those routes had no FEATURE_META entry telling the runner they need auth.

/api/privacy/rectify and /api/signals/top returned a plain 401 instead — they're guarded in the handler, not the proxy matcher — but the effect on the sweep was the same false fail.

§ 2The empty-BASE_URL bug — already fixed on main

The 9/7 sweep needed NULOGDASH_BASE_URL passed explicitly because NULOGDASH_BASE_URL= (empty) in .env.local defeated the ?? "http://localhost:3000" default. PR #117 (proxy.ts rename + nulogdash pipeline-runs tab) already changed it to process.env.NULOGDASH_BASE_URL?.trim() || "http://localhost:3000", which treats empty-string as unset. Nothing to fix here — verified on d534a30. (The explicit pass was still used this run, belt-and-braces.)

§ 4The one remaining failure

council-sample → 503 · OpenRouter 403: council T1 — all models failed

Not a nulogdash issue. PR #115 repointed the T1 seat to thinkingmachines/inkling-small:free, which is returning 403 for this account. runSeat treats 403 as fatal (auth-class, not retryable) and does not fall through to FREE_MODEL_CHAIN, so one 403 kills the whole seat and the deliberation with it. Likely an OpenRouter data-policy / privacy-setting gate on that specific model — check the account's model-access settings, or repoint T1. council-public passed this run and failed a prior one, so it is intermittent on model latency too — see the OpenRouter pipeline report.
