Scope note. The portfolio page renders two independent panels that users conflate because both say "Health":
  • Portfolio Health Score — deterministic 0–100 number from GET /api/portfolio/health. Currently fails with "Health score unavailable — try again shortly."
  • Portfolio Health Check · AI — LLM narrative from POST /api/portfolio/health-ai. Currently fails with "Health check returned empty — try again."
They fail for different reasons but share one root cause. This doc covers both.

Overview — the two data planes

The app deliberately splits state across two stores. This split is correct and is load-bearing in ~17 call sites; the bugs below are wiring defects, not architectural ones.

PlaneStoreOwnsKeyed by
User plane
nuwrrrld-portal		 Neon (Postgres) Watchlist tickers, Nu AI token usage, signal cache, council verdicts, live prices Clerk userId
Market plane
gcp3-backend		 Cloud Run + Firestore Finnhub quotes/profiles, signals, industry analytics, portfolio math Ticker set + date

The portal holds no Finnhub key. lib/shared/live-price.ts is only a parser — the actual Finnhub socket lives in a Modal worker (homebase/modal_finnhub_ws.py) that pushes into the portal via POST /api/signals/live. So the portal can never compute market data itself; it must ask gcp3. That constraint is why the split cannot be collapsed.

Step 7 in detail — the shared root cause

Both panels call the same upstream path, {MCP_BACKEND_URL}/api/portfolio/health. That endpoint is not implemented in gcp3. Grepping gcp3/backend/main.py and gcp3/backend2/main.py for any portfolio-health route returns nothing. The analysis logic exists in gcp3/backend/portfolio_analyzer.py (get_portfolio_analysis()) but was never registered as a FastAPI route.

  • Score panel → upstream non-OK → portal returns 502 → "Health score unavailable."
  • AI panel → fetchHealth swallows the failure and returns null → the AI still runs, but ungrounded, with the prompt literally saying "Portfolio health data: unavailable (no GCP3 backend connection)".

Bugs

#SevWhereDefectEffect
1P0 gcp3 backend/main.py /api/portfolio/health route never registered; portfolio_analyzer.py orphaned Both panels fail. Root cause of both messages.
2P0 contract gcp3 emits ai_grade (A–D), ai_concentration, ai_insights[]… Portal expects score (0–100), factors[], summary. Zero field overlap. Naively wiring the route yields score: 0 → Grade F for every user, silently. Worse than the current error.
3P1 health-ai/route.ts:97 max_tokens: 400 against a reasoning-capable chain (nemotron-3-*). Reasoning tokens consume the same budget. Model can exhaust the budget on hidden reasoning and emit zero delta.content → HTTP 200 + empty body → "returned empty". Compare /api/nuai which uses 1024.
4P1 lib/shared/sse.ts:30 Parser reads only choices[0].delta.content; ignores delta.reasoning and non-delta shapes. Any model that streams into a different field produces empty output with no diagnostic.
5P1 lib/openrouter.ts:157 fetchWithModelFallback falls back on HTTP status only. A model returning 200 with an empty completion is treated as success. No retry on the exact failure users see. One flaky free model = dead feature.
6P1 health-ai/route.ts:116 Mid-stream errors call ctrl2.error(err) after headers are flushed. Client already saw 200 OK; it cannot distinguish "upstream died" from "model said nothing". Both surface as "returned empty".
7P1 health-ai/route.ts No rate limit and no token accounting — unlike /api/nuai, which has checkRateLimit() + getRemainingBudget() + recordUsage(). Health checks bypass NU_AI_DAILY_TOKEN_BUDGET entirely. Unmetered cost path; spammable.
8P1 health/route.ts + gcp3 Portal never sends the user's tickers. gcp3's get_portfolio_analysis() falls back to a hardcoded 10-symbol DEFAULT_PORTFOLIO. Once the route exists, users would see a stranger's portfolio graded as their own. Footgun for a personalised score.
9P2 health-ai/route.ts:33 void userId; sits after the try/finally that always returns — unreachable dead code. The userId param is unused. Dead parameter; misleading signature.
10P2 PortfolioClient.tsx:186 setHealthError(err.message) surfaces raw internals, e.g. "SSE response body is not readable". Internal strings leak into the UI.
11P2 PortfolioClient.tsx No empty-watchlist guard. Prompt becomes "Watchlist tickers: none added yet". Model is asked to analyse nothing; may refuse or return whitespace → "returned empty" again.
12P1 health-ai/route.ts, brief/route.ts homebase/interactivity-15.md §3.1 specified Accept-based content negotiation for all three SSE routes. Only /api/nuai received it (wantsStream); these two always return a stream. Cross-surface. Legacy mobile builds expecting JSON get an unparseable stream → empty result. Independent cause of the same symptom. Documented plan, half-implemented.
13P1 mobile lib/usePortfolio.ts Mobile fetches the same dead /api/portfolio/health. The Portfolio tab's headline score is broken on mobile too — same root cause, not previously connected.

Why this went undetected

Three things independently masked the fault. Worth recording, because each is a repeatable trap:

  1. The button was disabled. homebase/nuwrrrld-portal-audit.md catalogued the route as "exists and calls GCP backend" and treated the problem as pure UI wiring — then un-disabled it. Re-enabling a control asserts that everything behind it works; that assertion was never end-to-end tested, only grep-verified at the route-file level.
  2. An earlier fix produced no visible change. A corrupted MCP_BACKEND_URL (literal \n in the prod env value) caused the identical "Health score unavailable" string on 2026-07-21 (recorded in the mobile wiki). Repairing it moved the failure from fetch throws (503) to 404 from gcp3 (502) — both render the same message. The fix was real; the symptom didn't move; the deeper cause stayed hidden. Do not re-diagnose this as an env-var problem.
  3. The AI panel never surfaced its own degradation. fetchHealth() catches everything and returns null, so the check has been silently running ungrounded since it shipped — producing confident portfolio prose with no portfolio data behind it. It looked like it worked.

Prior docs also anticipated this without closing it: docs/nuwrrrld-portal/launch-todo.md carries an unchecked "Brief / Health SSE routes — stream shape correct, empty/error states handled", and launch-copy.md markets "Portfolio Health Score — an A–F grade" as a headline launch feature. It is currently non-functional, and gcp3's grader tops out at A–D and never emits F.

Why "Health check returned empty" specifically

That message fires on exactly one condition in PortfolioClient.tsx: the request returned HTTP 200 and consumeSSE accumulated a zero-length string.

if (!finalText) {
  setHealthStatus("error");
  setHealthError("Health check returned empty — try again.");
}

So the network call succeeded. Ranked causes:

CauseConfidenceReasoning
Reasoning tokens exhaust max_tokens: 400 high Chain is led by nemotron-3-ultra/super, reasoning-capable. 400 is tight for a ~180-word grounded answer plus hidden reasoning. /api/nuai uses 1024 and is not reporting this.
Content arrives in a field consumeSSE ignores medium Parser is strict on delta.content. Silent-drop by design.
25 s AbortController fires before first token medium Free-tier queueing can exceed 25 s. Abort after headers → truncated stream, no error status.
Model refuses (empty watchlist / ungrounded prompt) low–med Because BUG-1 forces the prompt into "data unavailable" mode, the model is asked to grade a portfolio it was given no data for.

Not yet confirmed live. These are ranked from code inspection. Confirming requires logging the raw upstream SSE and the served model for one failing request — no such logging exists on this route today (see BUG-6: errors are swallowed into the stream).

Recommended fix order

StepRepoChange
1gcp3Add GET /api/portfolio/health?tickers=…. Stateless, no Clerk token — it is a pure function of the ticker list, and get_portfolio_analysis already caches by portfolio:{sorted_tickers}:{date}. Keeps user credentials off the external host.
2gcp3Add an adapter emitting the portal's contract: numeric score 0–100, factors[] (name/score/impact/description), summary, generated_at — derived from the existing concentration & industry-count signals. Fixes BUG-2.
3portalPass watchlist.map(w => w.ticker); short-circuit to an empty-state when the watchlist is empty instead of letting gcp3 grade DEFAULT_PORTFOLIO. Fixes BUG-8, BUG-11.
4portalRaise max_tokens to 1024; treat an empty completion as a failure inside fetchWithModelFallback so the chain actually falls through. Fixes BUG-3, BUG-5.
5portalBuffer the first token before flushing headers, so upstream failures can still return a real status code. Fixes BUG-6.
6portalApply the /api/nuai rate-limit + token-budget guards to health-ai. Fixes BUG-7.
7portalHousekeeping: drop dead void userId, stop surfacing raw err.message. Fixes BUG-9, BUG-10.
Architecture verdict. Keep the Neon / gcp3 split. The one simplification worth taking is removing the Clerk token from the gcp3 call (step 1) — the endpoint needs no user identity, and app/api/portfolio/health/route.ts already carries the comment "Fail-closed: don't fall back to a hardcoded external host with a user token." A stateless endpoint retires that hazard outright.
