Improvement 1  ·  Subscription reliability

First-time subscribers actually get their Pro access now

Before PR #11, signing up and paying through the mobile app would silently fail to unlock Pro features. The Stripe webhook that grants entitlements couldn't find the user because a critical piece of identifying data — the Clerk user ID — was never written to the Stripe Customer record. New subscribers would complete checkout but land back in the app still seeing the free-tier paywall.

Before New subscriber pays → webhook fires → Stripe Customer has no clerk_user_id → sync silently skipped → user stuck on free tier despite paying.
After On checkout.session.completed the user ID is stamped onto the Customer → sync runs immediately → Pro access granted within seconds of payment.
Webhook fix Entitlement sync Stripe + Clerk

Improvement 2  ·  Post-purchase clarity

A clear "your trial has started" moment after checkout

Completing a subscription used to drop the user silently back onto the dashboard with no feedback — leaving them wondering whether the payment went through. PR #10 added a green confirmation banner that appears immediately after redirect and auto-dismisses, with a direct link to the billing page to review plan details.

  • Dashboard reads the ?checkout=success query param injected by Stripe's redirect
  • Banner confirms the 7-day free trial is active
  • One-tap link to /dashboard/billing for plan management
  • No extra page load — handled entirely within the existing dashboard route
Billing UX Post-checkout flow Zero extra routes

Improvement 3  ·  Retention & re-engagement

Weekly digests, streak tracking, and trial nudges keep users coming back

PR #9 wired up three separate retention mechanisms that work in the background to reduce churn and bring lapsed users back to the app — all without requiring any action from the user to set them up.

  • Weekly digest emails — a cron-triggered endpoint sends each Pro user their top signals for the week via Resend, respecting email preferences and verified-email requirements
  • Streak API — records daily app opens; same-day POSTs are idempotent (no accidental double-counting)
  • Trial nudge emails — automatically sent to trialling users approaching expiry, capped at 3 sends per user so they never become spam
  • Annual upsell page at /dashboard/upgrade shows monthly subscribers the $9.99 → $6.58/mo savings from switching to annual
Email automation Streak tracking Trial nudge Annual upsell

Improvement 5  ·  Discoverability & portfolio tools

Search engines can find the app — and it now has real portfolio intelligence

PRs #6 and #7 together moved the app from "invisible on the web with no financial tools" to "discoverable across three keyword clusters with a full portfolio analysis backend."

  • Portfolio health score — proxies the MCP backend, normalises to a typed PortfolioHealth shape, graded A–F, cached 15 min per user
  • Optimizer suggestions — each item carries a required disclaimer; prevents the app from appearing to give direct financial advice
  • Watchlist CRUD — GET / POST / DELETE per ticker via /api/portfolio/watchlist
  • Referral seed API — generates unique codes, guards against self-referral and double-redemption
  • Three SEO landing pages — /signals, /ai-assistant, /portfolio-intelligence — each targets a distinct keyword cluster so they don't cannibalise each other
  • Sitemap + robots — Next.js native routes; disallows /dashboard/ and /api/ from crawlers
  • Organisation JSON-LD structured data on root layout for rich search results
Portfolio health API SEO landing pages Sitemap / robots Watchlist Referral API
Landed in PR #6 & PR #7

Improvement 6  ·  Core AI value proposition

Real-time stock signals with explainability, plus a personal AI finance assistant

PR #5 delivered the two features that define what NuWrrrld is: a signal digest that shows users actionable trade ideas with transparent reasoning, and an AI assistant that can discuss those signals in the context of the user's actual portfolio — all with built-in guardrails and a "not financial advice" disclaimer on every response.

Before The dashboard was a shell. Users who signed up for financial intelligence had nothing to look at.
After Pro users land on a live signal digest with confidence scores, time horizons, and expandable "Why this signal" cards — plus a chat window where they can ask follow-up questions answered by Claude with their portfolio as context.
  • Signals fetched in parallel from two optimiser sources and merged into a single DigestPayload schema — adapter normalises both response shapes
  • 15-minute per-user cache avoids hammering upstream APIs on every page load
  • Nu AI is gated behind the nu_ai entitlement — free users see an upgrade prompt, not an error
  • 50 k daily token budget tracked in-memory per user; 429 returned (not a silent truncation) when exceeded
  • Guardrail layer refuses off-topic queries before they reach Claude, keeping costs predictable
  • Portfolio context injected into every AI prompt so answers are personalised, not generic
Signal digest Nu AI assistant Entitlement gate Daily token budget Guardrails
Landed in PR #5
