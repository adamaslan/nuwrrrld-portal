Optimization order

Ranked by tokens saved per session, highest first.

01

Scope global CLAUDE.md's Python guide out of non-Python repos

The entire 7.2K-token file is Python conventions (dataclasses, type hints, pytest patterns) plus the safety rules and wiki-on-PR rule. This is a Next.js/TypeScript repo — none of sections 1–27 apply here. Move the Python guide to a separate file and reference it conditionally, keeping only the safety rules, doc-archiving policy, and wiki-on-PR rule in the always-loaded root.

saves ~6.5K tok/session here
02

Merge the four git-workflow rules into one document

multi-branch-optimization, one-session-one-worktree, no-conflicts1, and stay-on-branch-after-merge already cross-reference each other constantly and share the same worked example (PRs #89/#91). One consolidated git-workflow.md — branch-per-unit, worktree isolation, merge ordering, never-return-to-main — as a single ~2.5K-token doc replaces 6.4K across four files.

saves ~3.9K tok/session
03

Make mamba-rules.md directory-scoped, not global

2.6K tokens of mamba/conda environment conventions, relevant only to the handful of Python projects listed in its own table. Move it to a per-project CLAUDE.md in those directories, or a project-scoped rules file — it currently loads even here, where it applies to nothing.

saves ~2.6K tok/session here
04

Fold handoff-at-half-context into context-bloat-warning

These two already describe one workflow split across two files — the tier system and the action it triggers. Combined they'd run under 1.2K tokens instead of 1.6K, and the single-offer-per-tier logic reads as one coherent state machine instead of a rule referencing a rule.

saves ~0.4K tok/session
05

Leave fixy-rule, mobile-web-wiki-sync, and artifact-and-local-html as-is

These are already single-purpose and reasonably tight. If load cost matters more than always-on enforcement, they're candidates for converting to on-demand skills (loaded via the Skill tool only when a matching task appears) rather than standing CLAUDE.md rules — but that trades a hook-enforced guarantee for a maybe-skipped one, which is a real behavior change worth deciding deliberately.

Estimates use ~4 chars/token on raw file bytes and don't include the skill listing, the ~250-entry deferred-tool name index, or MCP server instructions also present in this session — all separate overhead from the rule files measured here. Applying fixes 01–04 would cut this session's rule-file load from ~21.4K to roughly ~7.9K tokens, a 63% reduction, without removing any enforcement — the hooks that back these rules (worktree-guard, no-conflicts-guard, wiki-guard, fixy-guard) read the consolidated files exactly the same way.
